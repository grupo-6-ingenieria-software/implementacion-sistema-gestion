# CU54: exportación común e integración mensual

Se implementa la base transversal de CU54 y el adaptador de CU47 (`ventas-mensuales`). CU20, C33 y CU45 conservan su comportamiento; los demás productores de reportes no se implementan aquí. No se agregan tablas ni migraciones.

## Contrato y recorrido

UI06 (`AccionExportarFormato`, modo `report`) envía `{ tipo, periodo, filtros? }` por `reporte:exportar-pdf` o `reporte:exportar-xlsx`. Main valida JWT, sesión y rol efectivo de Dueño, normaliza el descriptor y recalcula mediante el productor mensual. Filas, identidad, nombre y ruta aportados por el renderer no gobiernan el resultado.

`src/shared/reports.ts` contiene el contrato común. `report-registry.ts` registra solamente el productor mensual. Un tipo documentado sin productor devuelve `NOT_IMPLEMENTED`; un descriptor inválido no se despacha a reabastecimiento. Para conectar futuros productores se necesitará un adaptador con normalización, carga autorizada, criterio específico de datos, etiquetas, fragmentos seguros de nombre y builders; sus cálculos pertenecen al productor.

El selector nativo elige una carpeta. Main fija `VentasMensuales_YYYY-MM_DD-MM-AAAA.pdf` o `.xlsx` y solicita confirmación para reemplazar el archivo exacto. Un solo instante, presentado en `America/Santiago`, alimenta encabezado, nombre y auditoría. PDF incluye gráfico; XLSX conserva valores diarios numéricos sin imagen.

## Finalización y recuperación

`report-export-service.ts` coordina generación, revalidación de sesión, archivo temporal, auditoría y publicación. `report-export-audit.ts` crea/resuelve `UsuarioVersion` e inserta una auditoría por UUID de operación dentro de una transacción. No utiliza callbacks con reintentos automáticos. El dispatcher excluye estas operaciones de su auditoría posterior.

`report-export-file.ts` usa temporales exclusivos y respaldo del destino confirmado. Publica el archivo completo mediante un enlace duro en el mismo directorio, evitando sobrescribir un archivo creado por otro proceso durante la operación. Si el filesystem no admite enlaces duros (FAT32/exFAT de pendrives y algunos recursos de red), publica una copia creada en modo exclusivo (`wx`), que tampoco sobrescribe un archivo ajeno; si la copia falla, elimina su archivo parcial, restaura el destino anterior y devuelve E1. Solo elimina artefactos propios con huellas esperadas.

`saved` exige archivo y auditoría confirmados. Un fallo conocido revierte la transacción y restaura el destino anterior. Sin datos exportables o ante fallo de generación/archivo se muestra **“No fue posible generar el archivo”**. Cancelar ubicación o reemplazo devuelve `cancelled`. Un fallo de limpieza posterior a la confirmación conserva el éxito y registra el diagnóstico.

No existe atomicidad distribuida entre libSQL y el filesystem. Una confirmación incierta devuelve `EXPORT_RECONCILIATION_REQUIRED` con UUID, conserva evidencia privada en `userData/report-export-pending` y bloquea nuevas finalizaciones en ese destino. La evidencia contiene descriptor normalizado, rutas propias, huellas, identidad y metadatos de auditoría; no contiene JWT ni filas del reporte.

**Verificar exportación** llama a `reporte:conciliar-exportacion` con `{ operacionId }`, exclusivamente para Dueño. Las rutas se leen de la evidencia validada. Una transacción de escritura en el cliente primario espera al escritor previo y contrasta la auditoría por UUID; la mera ausencia en un SELECT suelto no autoriza compensación. Auditoría coincidente y archivo intacto confirman el resultado original sin nueva auditoría. Ausencia concluyente permite restauración. Base inaccesible, archivo alterado, evidencia incompatible o restauración imposible conservan `pending`.

La evidencia se lee después de reiniciar al elegir el mismo destino; no se concilia automáticamente. La verificación usa leases exclusivos por proceso. Una lease de un proceso terminado no impide la recuperación explícita; no se eliminan leases ajenas para resolverla. Procesos aún vivos o cuya terminación no pueda comprobarse mantienen el bloqueo. No se borra ni modifica una auditoría confirmada.

## Ejecución aislada

En PowerShell, antes de ejecutar pruebas:

```powershell
$env:DATABASE_URL = 'file::memory:'
$env:DATABASE_AUTH_TOKEN = ''
npm run typecheck
npm test
npm run build
node tests/renderer/cu47-ui.mjs
node tests/main/report-export-electron.mjs
```

El harness de interfaz usa Chrome/Edge instalado o `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Las pruebas Electron usan impresión real y SQLite temporal; el diálogo de carpeta se sustituye para evitar interacción. Los archivos y capturas quedan bajo `out/cu54-qa` y `out/cu47-qa` (ignorados por Git). Los fallos de red/commit se simulan; no se provocan contra una base remota real. `build` no empaqueta ni publica.

La aceptación de la exportación de los otros siete reportes requiere productores y verificaciones específicos cuando estén disponibles.
